# Test plan and quality gates

## Automated checks
Run in the project directory:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m compileall -q app scripts
```

GitHub Actions runs tests on pushes and pull requests. The tests use an isolated, temporary SQLite database and generated test credentials; no real API calls are made.

## Coverage targets
| Test area | Expected behavior |
| --- | --- |
| Authentication | Invalid login rejected, correct login sets secure-style session cookie |
| Authorization | Private lead reads require session; writes require CSRF |
| Validation | At least email or phone; invalid email and unknown enum rejected |
| Scoring | Deterministic budget+timeline+service+source factors and thresholds |
| CRUD | Create, list, view, update, add note, delete |
| Dashboard | Counts change as leads are created/deleted |
| Export | CSV header, escaped formula payloads, authenticated access |
| Templates | Offline draft returns editable text and never dispatches |
| AI guard | AI mode requires explicit confirmation and configured key |
| Public intake | Accepts consent-marked demo inquiry; honeypot does not insert lead |

## Manual user acceptance tests
1. Start with `.env` generated by bootstrap; log in through browser.
2. Add fictional demo lead; verify its score and factors.
3. Filter by priority; change to `contacted`; set a past follow-up and verify due counter.
4. Generate a local draft, copy it; verify nothing is automatically sent.
5. Add a note, export CSV, delete the record.
6. Open the public form in a private browser and submit fictional details.
7. Resize viewport to 360px mobile width and check fields/tables/modal controls.
8. Confirm `.env` and DB files do not appear in `git status`.

## Explicitly not verified
Large-scale load performance, public-host deployment, email deliverability, paid AI quality and compliance certification. Never claim these tests were performed without evidence.
