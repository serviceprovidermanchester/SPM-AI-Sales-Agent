# Technical Requirements Document (TRD)

## 1. System overview
A FastAPI application serves static dashboard files and a JSON API. SQLite provides embedded persistence. Most workflows are synchronous and local. AI draft creation makes one on-demand HTTPS request to the configured OpenAI Responses API, only after an admin confirms external processing.

## 2. Runtime dependencies
- Python >=3.11; FastAPI; Uvicorn; Pydantic with email validation; python-dotenv; itsdangerous; httpx.
- Frontend: HTML5, CSS3 and modern vanilla JavaScript (no CDN, no frontend build step).
- Storage: SQLite database at `DATABASE_PATH` (defaults to `data/app.db`).
- Optional remote dependency: OpenAI Responses API (network access, valid key and enabled account model).

## 3. Interfaces
- Browser → `/`, `/capture`, `/static/*` (static files).
- Browser → `/api/auth/*` for login/session/logout.
- Admin → `/api/dashboard`, `/api/leads`, `/api/leads/{id}` and subordinate actions.
- Public inquiry form → `/api/public/leads`.
- Optional AI request → `https://api.openai.com/v1/responses`.

## 4. Authentication and input protection
- Password compared with `hmac.compare_digest` to `.env` value; unique random password generated by bootstrap.
- Signed HttpOnly cookie (`itsdangerous`), `SameSite=Strict`; session lifetime is eight hours.
- CSRF token returned after successful login; required for private mutations.
- Login throttled to 10 attempts per 15 minutes per client IP in process memory.
- Public submissions capped at five per hour per IP in memory; basic honeypot.
- Pydantic validates enums, contact method and string lengths; parameterized SQL for queries.
- HTML escapes all untrusted API content before placing it into templates.

**Limitations:** No user roles, credential hashing, distributed rate limiter, reverse-proxy trust configuration, managed secrets or external threat testing. Use behind loopback for demonstration.

## 5. Data model
`leads` includes identifying details, source/service/budget/timeline, consent flag, status, score, priority and follow-up timestamp. `activities` stores notes and timeline events associated with a lead, deleting automatically when the lead is removed. See `DATABASE.md` for complete field definitions.

## 6. API design
JSON endpoints use standard HTTP status codes. Admin read calls require a signed cookie; admin writes require a signed cookie plus `X-CSRF-Token`. Public form accepts validated JSON and returns `201`. Full contract and examples are in `API.md`. FastAPI also exposes interactive docs at `/docs`.

## 7. Fault handling
- Validation errors: 422.
- Missing or expired session: 401.
- Missing CSRF token: 403.
- Unknown lead: 404.
- Rate limited: 429.
- Missing bootstrap configuration: 503.
- External AI outage: 502 with a safe generic message. The admin can create a local template draft instead.

## 8. Non-functional targets (prototype, not audited)
- Runs locally on mainstream laptops without external infrastructure.
- No CDN dependency; responsive CSS for mobile.
- DB transactions are short and SQLite foreign keys enabled.
- Suggested <200 ms for CRUD operations on a small, local dataset. **This is a target, not a measured benchmark.**
- Single-process use. No promise of uptime, horizontal scale or regulatory certification.

## 9. Test and deployment requirements
- Automated tests: auth/CSRF, scoring, intake, CRUD, notes, draft behavior, export, filtering and error conditions.
- Local run scripts are primary deployment mode.
- Docker Compose binds only localhost by default.
- For Internet-facing deployments, add TLS, secure cookies, proper identity/access controls and storage backups before using any real data.

## 10. Version and change policy
Version number `0.1.0` denotes a demonstration prototype. Changes to schema or endpoints should be documented and validated with tests. No automated database migrations are provided in this version.
